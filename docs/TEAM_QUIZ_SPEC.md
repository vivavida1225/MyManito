# 팀별 비밀 퀴즈 기능 최종 명세

- 문서 상태: 확정
- 작성일: 2026-08-02
- 적용 프로젝트: MyManito

## 1. 목적

활성 상태인 마니또 팀에서 관계별 비밀 퀴즈를 반복 운영한다. 각 참가자는 자신에 관한 시스템 질문의 기준 답안을 먼저 입력하고, 자신을 챙기는 마니또는 그 답을 추측한다. 기준 답안 작성자는 마니또의 풀이를 평가하고, 결과는 팀 리더보드 점수와 최종 퀴즈 점수율에 반영한다.

이 기능은 다음 원칙을 따른다.

- 퀴즈 모드는 관리자가 명시적으로 활성화한다.
- 모든 기간 경계는 팀에 저장된 관리자 시간대와 기준 시간을 따른다.
- 질문, 답안, 평가, 점수 정산은 회차별로 추적 가능해야 한다.
- 결과 공개 전에는 나를 챙기는 마니또의 신원을 노출하지 않는다.
- 자동 제출, 자동 평가 및 점수 반영은 중복 실행되지 않아야 한다.

## 2. 용어

### 2.1 참가자 역할

- **기준 답안 작성자**: 자신에 관한 질문을 받고 기준 답안을 입력하는 참가자
- **풀이자**: 기준 답안 작성자를 챙기는 마니또
- **평가자**: 풀이자의 답안을 평가하는 기준 답안 작성자
- **풀이 대상**: 풀이자가 챙겨주는 참가자

현재 관계에서 참가자 A의 `assigned_to`가 참가자 B라면 다음과 같다.

- B가 기준 답안 작성자다.
- A가 B를 챙기는 마니또이자 B의 문제를 푸는 풀이자다.
- B가 A의 풀이 답안을 평가한다.

### 2.2 질문 종류

- **관리자 지정 공통 질문**: 관리자가 다음 회차용으로 직접 등록하며 모든 참가자에게 동일하게 배정되는 질문
- **시스템 기본 질문**: 관리자가 공통 질문을 지정하지 않았을 때 시스템 질문 풀에서 참가자별로 무작위 배정되는 질문

참가자 화면에는 질문 종류를 다음과 같이 명시한다.

- 관리자 지정 공통 질문: `공통 퀴즈!`
- 시스템 기본 질문: `랜덤 퀴즈!`

### 2.3 답안과 점수

- **기준 답안**: 기준 답안 작성자가 입력하고 확정한 변경 불가능한 답
- **풀이 답안**: 풀이자가 풀이기간 동안 임시 저장하는 답
- **평가점수**: 평가자가 풀이 답안에 부여하는 1점부터 5점까지의 원점수
- **퀴즈 점수 배수**: 평가 원점수를 리더보드 점수로 변환할 때 사용하는 서버 전역 설정값. 초기값은 3이다.
- **퀴즈 점수율**: 퀴즈 배수 적용 전 원점수를 기준으로 계산한 최종 성과 비율

## 3. 퀴즈 모드 활성화 조건

### 3.1 기본 상태

- 신규 팀과 기존 팀 모두 퀴즈 모드 기본값은 `OFF`다.
- 팀 관리자만 퀴즈 설정을 조회하고 변경할 수 있다.
- 팀 관리자가 참가자로 Claim하지 않은 경우에도 관리자 설정은 사용할 수 있다.
- 참가자로 Claim하지 않은 관리자는 참가자용 `비밀 퀴즈` 메뉴를 사용할 수 없다.

### 3.2 모든 참여자 Claim 완료

- 퀴즈 모드는 팀의 모든 Participant가 Claim을 완료한 경우에만 활성화할 수 있다.
- 마지막 미확인 참여자가 Claim을 완료하여 최초로 전원 Claim 상태가 되면 관리자에게 알림을 보낸다.
- 알림 제목과 본문은 전원 Claim 완료와 퀴즈 모드 활성화 가능 상태를 명확히 전달한다.
- 알림 CTA `퀴즈 모드 켜기`는 해당 팀의 관리자 퀴즈 설정으로 이동한다.
- 알림은 인앱 알림으로 생성하고, 관리자가 푸시를 허용한 기기에도 전송한다.
- 활성화 요청 시점에도 전원 Claim 상태인지 서버에서 다시 검증한다.

### 3.3 활성화 이후 Claim 변경

- 퀴즈 모드가 켜져 있거나 정산되지 않은 회차가 남아 있으면 관리자가 Participant의 Claim을 해제할 수 없다.
- Claim 해제가 필요하면 먼저 퀴즈 모드를 끄고 시작된 회차의 정산 또는 취소가 끝나야 한다.

## 4. 관리자 설정

관리자는 다음 항목을 설정할 수 있다.

| 설정 | 기본값 | 제약 |
|---|---:|---|
| 퀴즈 모드 | OFF | 전원 Claim 완료 후에만 ON 가능 |
| 관리자 시간대 | `Asia/Seoul` | 읽기 전용, API 변경 불가 |
| 기준 시간 | 오후 12시 | 0시~23시 정각, 진행 중 회차가 없을 때 변경 가능 |
| 기준 답안 입력일수 | 2일 | 최소 1일 |
| 풀이일수 | 3일 | 최소 1일 |
| 다음 회차 공통 질문 | 없음 | 선택값, 다음 한 회차에만 적용 |

다음 검증 규칙을 적용한다.

- 회차 주기는 별도 입력값으로 저장하지 않고 `기준 답안 입력일수 + 풀이일수`로 계산한다.
- 회차 주기는 최소 2일, 최대 7일이다.
- 두 기간 중 하나라도 1일 미만이거나 합계가 7일을 초과하면 저장을 거부한다.
- 퀴즈 점수 배수는 팀 관리자 설정이 아니라 서버 전역 설정으로 관리하며 초기값은 3이다.

### 4.1 설정 변경 시점

- 진행 중 회차의 질문 종류, 질문 본문, 기간, 시작 및 마감 시각은 변경하지 않는다.
- 기준 답안 입력일수와 풀이일수 변경은 다음 회차부터 적용한다.
- 기준 시간 변경은 진행 중 회차의 확정된 마감을 바꾸지 않으며, 진행 중 회차가 없을 때만 저장한다.
- 관리자 지정 공통 질문은 아직 시작하지 않은 다음 회차에 적용한다.
- 공통 질문은 다음 회차 시작 전까지 등록, 교체 또는 삭제할 수 있다.
- 공통 질문은 회차가 시작되면 소비되고 설정값에서 비운다.

### 4.2 퀴즈 모드 비활성화

- 관리자가 퀴즈 모드를 끄면 새로운 회차를 생성하지 않는다.
- 이미 시작된 회차는 기준 답안 입력, 풀이, 평가 및 정산까지 정상 진행한다.
- 기존 회차가 모두 정산 또는 취소된 뒤 완전한 비활성 상태가 된다.
- 다시 활성화할 때도 전원 Claim 상태를 검증한다.
- 재활성화 후 첫 회차는 재활성화 시점 다음으로 도래하는 관리자 시간대의 기준 시간에 시작한다.

## 5. 시간대와 회차 경계

### 5.1 관리자 시간대

- 모든 퀴즈 날짜와 마감은 팀에 저장된 `quiz_timezone`을 기준으로 한다.
- 시간대는 `Asia/Seoul`과 같은 IANA 시간대 식별자로 저장한다.
- 관리자 설정 화면에는 저장된 시간대를 읽기 전용으로 표시한다.
- 시간대는 설정 API로 변경할 수 없으며 새 설정의 기본값은 `Asia/Seoul`이다.
- 관리자 기기나 현재 위치가 바뀌어도 저장된 회차 기준 시간대는 바뀌지 않는다.

### 5.2 기준 시간과 최초 회차 시작

- 관리자가 정한 기준 시간은 저장된 관리자 시간대에서 매일 퀴즈 날짜가 바뀌는 정각이다.
- 기본 기준 시간은 오후 12시다.
- 퀴즈 모드를 켜면 활성화 시각 이후 가장 먼저 도래하는 기준 시간에 첫 회차를 시작한다.
- 활성화 시각이 기준 시간과 정확히 같으면 즉시 시작하지 않고 다음날 기준 시간에 시작한다.
- 활성화 후 첫 회차가 시작되기 전까지 관리자는 기간과 다음 공통 질문을 변경할 수 있다.

### 5.3 기간 범위

회차 `n`의 시작을 `S`, 기준 답안 입력일수를 `A`, 풀이일수를 `Q`라고 할 때 기간은 다음 반개구간으로 정의한다.

```text
기준 답안 입력기간: [S, S + A일)
풀이기간:           [S + A일, S + A일 + Q일)
회차 주기:          A + Q일
```

- 시작 시각은 포함하고 종료 시각은 포함하지 않는다.
- 마감 시각 이후 서버에 도착한 저장 요청은 거부한다.
- 풀이기간 종료 시점은 다음 회차 시작 시점과 같다.
- 퀴즈 모드가 켜져 있으면 회차 사이에 별도의 공백을 두지 않는다.

### 5.4 평가기간

- 회차 `n`의 평가기간은 해당 회차의 풀이기간이 종료되는 시점에 시작한다.
- 평가기간 길이는 회차 `n`에 적용됐던 기준 답안 입력일수와 같다.
- 평가기간은 일반적으로 회차 `n+1`의 기준 답안 입력기간과 겹쳐 진행한다.
- 다음 회차의 입력일수가 변경되더라도 이미 시작된 이전 회차의 평가 마감은 바뀌지 않는다.
- 퀴즈 모드를 OFF로 전환하여 다음 회차가 없더라도 기존 회차의 평가기간은 유지한다.

```text
평가기간: [회차 n 풀이 종료, 회차 n 풀이 종료 + 회차 n 입력일수)
```

## 6. 회차와 관계별 퀴즈 생성

### 6.1 회차 생성

- 회차 시작 시 팀 회차 레코드를 한 번만 생성한다.
- 회차에는 적용된 시간대, 입력일수, 풀이일수, 각 기간 경계 및 질문 설정을 스냅샷으로 보관한다.
- 설정을 나중에 변경해도 기존 회차 스냅샷은 변경하지 않는다.

### 6.2 참가자별 퀴즈

- 회차마다 각 Participant를 기준 답안 작성자로 하는 관계별 퀴즈를 하나 생성한다.
- 해당 Participant를 `assigned_to`로 지목한 유일한 Participant가 풀이자다.
- 관리자 지정 공통 질문이 있으면 모든 관계별 퀴즈에 같은 질문을 배정한다.
- 공통 질문이 없으면 각 기준 답안 작성자에게 시스템 기본 질문을 독립적으로 무작위 배정한다.
- 무작위 배정 결과는 최초 생성 시 확정하며 새로고침이나 재접속으로 바꾸지 않는다.
- 서로 다른 참가자는 같은 회차에 같은 시스템 기본 질문을 받을 수 있다.
- 질문 종류와 배정 당시 질문 본문을 관계별 퀴즈에 보존한다.

### 6.3 질문 중복 금지

- 동일 팀의 동일 Participant에게 이미 배정했던 질문을 다시 배정하지 않는다.
- 중복 금지는 시스템 기본 질문과 관리자 지정 공통 질문 모두에 적용한다.
- 시스템 기본 질문은 안정적인 질문 ID로 중복을 판단한다.
- 관리자 지정 공통 질문은 앞뒤 공백과 연속 공백을 정규화한 본문을 기준으로 중복을 판단한다.
- 이미 배정된 공통 질문을 다음 회차 질문으로 등록하려 하면 저장을 거부하고 다른 질문을 입력하도록 안내한다.
- 취소된 회차라도 참가자에게 질문이 공개됐다면 배정 이력에는 포함한다.

### 6.4 질문 풀 소진

- 재배정 가능한 시스템 기본 질문이 없고 관리자 지정 공통 질문도 없으면 새 회차를 시작하지 않는다.
- 시스템은 퀴즈 모드를 OFF로 전환하고 관리자에게 질문 풀 소진 알림을 보낸다.
- 생성하지 못한 회차에는 누구에게도 기본점수, 보상 또는 감점을 부여하지 않는다.
- 관리자가 새로운 공통 질문을 지정하고 퀴즈 모드를 다시 켜면 다음으로 도래하는 기준 시간부터 다시 시작할 수 있다.

## 7. 참가자 UX

### 7.1 비밀 퀴즈 메뉴

- Claim을 완료한 팀 참가자의 팀별 대시보드에 `비밀 퀴즈` 메뉴를 제공한다.
- 한 사용자가 기준 답안 작성자, 풀이자 및 평가자 역할을 동시에 가질 수 있으므로 역할별 할 일을 구분해 보여준다.
- 화면은 최소한 다음 영역을 제공한다.
  - 이번 회차에 내가 입력할 기준 답안
  - 내가 챙겨주는 사람에 관해 풀 퀴즈
  - 나를 챙기는 마니또가 제출한 직전 회차 답안 평가
  - 내가 직전 회차에 받은 평가 결과

### 7.2 기준 답안 확정

- 기준 답안 입력기간이 시작되면 질문과 `공통 퀴즈!` 또는 `랜덤 퀴즈!` 표시를 보여준다.
- 기준 답안은 공백만으로 확정할 수 없다.
- 사용자가 `정답 확정`을 누르면 정말 이 답안으로 확정할지 확인 모달을 표시한다.
- 사용자가 모달에서 다시 확인한 경우에만 서버에 확정 요청을 보낸다.
- 한 번 확정된 기준 답안은 사용자와 관리자 모두 변경할 수 없다.
- 중복 요청은 같은 결과를 반환하고 답안을 새로 만들거나 바꾸지 않는다.
- 기준 답안 작성자는 확정 후 자신의 질문과 기준 답안을 다시 확인할 수 있다.

### 7.3 풀이 답안 임시 저장과 자동 제출

- 기준 답안이 정상 확정된 관계만 풀이기간에 풀이자에게 문제를 제공한다.
- 풀이기간 동안 풀이자는 답안을 여러 번 임시 저장하고 수정할 수 있다.
- 임시 저장은 최종 제출이 아니며 별도의 확정 모달을 표시하지 않는다.
- 풀이기간 종료 시 서버에 저장된 마지막 비어 있지 않은 답안을 자동 제출한다.
- 저장된 답안이 없거나 공백뿐이면 미제출로 처리한다.
- 풀이기간 종료 후에는 풀이 답안을 생성하거나 변경할 수 없다.
- 자동 제출은 정확히 한 번만 처리한다.

### 7.4 평가 확정

- 풀이기간이 끝나고 풀이 답안이 제출된 경우 기준 답안 작성자에게 평가 UI를 제공한다.
- 평가자는 풀이 답안을 보고 1점부터 5점까지 선택한다.
- 평가자가 `평가 확정`을 누르면 확인 모달을 표시한다.
- 모달에서 다시 확인한 경우에만 평가를 확정한다.
- 한 번 확정한 평가점수는 변경할 수 없다.
- 평가기간이 끝날 때까지 확정하지 않으면 미평가 자동 정산 규칙을 적용한다.

### 7.5 결과 확인

- 풀이자는 자신의 평가가 확정된 직후 기준 답안과 받은 평가점수를 확인할 수 있다.
- 미평가 자동 정산은 평가기간 종료 후 확인할 수 있다.
- 풀이 미제출 결과는 풀이기간 종료 후 기준 답안과 0점 결과를 확인할 수 있다.
- 기준 답안 미입력 회차는 풀이자에게 `이번 회차 휴식`과 기본점수 지급 사실을 안내하되 퀴즈 점수율에는 포함하지 않았음을 표시한다.
- 퀴즈 화면에는 평가 원점수는 보여줄 수 있지만, 그로 인해 증감한 정확한 리더보드 점수나 진행 중 총점은 보여주지 않는다.

## 8. 종료 예정일과 다음 회차 진행 결정

### 8.1 종료 예정일의 성격

- 팀의 종료 예정일은 안내용 날짜이며 도래했다고 팀을 자동 종료하지 않는다.
- 실제 팀 종료는 관리자의 팀 종료 작업으로 발생한다.
- 종료 예정일 충돌 판단에는 `quiz_timezone` 기준 종료 예정일 00:00을 사용한다.

### 8.2 충돌 조건

다음 회차의 풀이 시작과 종료를 각각 `Q_START`, `Q_END`, 종료 예정일의 관리자 시간대 자정을 `E`라고 할 때 다음 조건이면 충돌로 판단한다.

```text
Q_START <= E < Q_END
```

- `E == Q_START`이면 충돌이다.
- `E == Q_END`이면 충돌이 아니다.
- 종료 예정일이 평가기간에만 포함되는 경우에는 이 사전 승인 UX를 적용하지 않는다.

### 8.3 조건부 회차 진행 UX

- 충돌 회차의 기준 답안 입력기간은 예정대로 시작한다.
- 회차는 관리자 결정 대기 상태임을 참가자 화면에 표시한다.
- 참가자는 결정 대기 중에도 기준 답안을 입력하고 확정할 수 있다.
- 입력기간 시작 시 관리자에게 종료 예정일 충돌 알림을 보낸다.
- 관리자에게 다음 선택지를 제공한다.
  - `이번 회차 진행`
  - `이번 회차 취소`
- 관리자는 해당 회차의 기준 답안 입력기간이 끝나기 전까지 결정해야 한다.
- 진행 결정과 취소 결정은 한 번 확정하면 변경할 수 없다.

### 8.4 결정 결과

- `이번 회차 진행`을 선택하면 입력기간 종료 후 정상적으로 풀이기간을 시작한다.
- 진행을 승인해도 관리자가 실제 팀을 조기 종료하면 미정산 회차 취소 규칙을 적용한다.
- `이번 회차 취소`를 선택하면 즉시 회차를 취소하고 참가자에게 취소 사실을 알린다.
- 관리자가 입력기간 마감까지 응답하지 않으면 `이번 회차 취소`와 동일하게 처리한다.
- 취소된 회차에 입력된 기준 답안은 어떤 점수 계산에도 사용하지 않는다.
- 취소된 회차에는 기본점수, 평가 보상 또는 감점을 부여하지 않는다.
- 취소 후 새로운 회차가 생성되지 않도록 퀴즈 모드를 OFF로 전환한다.

### 8.5 종료 예정일 변경

- 종료 예정일 또는 퀴즈 기간 설정이 바뀌면 아직 시작하지 않은 다음 회차의 충돌 여부를 다시 계산한다.
- 기준 답안 입력기간 중 종료 예정일을 변경하여 새 충돌이 발생하면 관리자에게 즉시 같은 결정을 요구한다.
- 이미 풀이기간에 들어간 회차와 충돌하도록 종료 예정일을 변경하려면 종료 예정일 저장 과정에서 진행 경고를 명시적으로 확인해야 한다.

## 9. 팀 조기 종료

- 관리자는 기존 팀 종료 기능으로 언제든 팀을 종료할 수 있다.
- 팀 종료 시점까지 정산이 완료된 퀴즈 결과만 최종 점수에 반영한다.
- 기준 답안 입력 중, 풀이 중 또는 평가 중인 회차는 모두 취소한다.
- 취소된 미정산 회차에는 기본점수, 자동 평가점수, 평가 보상 또는 미평가 감점을 부여하지 않는다.
- 마감은 지났으나 자동 정산 작업만 아직 실행되지 않은 회차는 팀 종료 트랜잭션에서 먼저 마감 시각을 기준으로 정산한 후 팀을 종료한다.
- 팀이 종료된 뒤에는 새로운 기준 답안, 풀이 답안 또는 평가를 받을 수 없다.

## 10. 점수 정산

### 10.1 기본 원칙

- 평가 원점수와 리더보드 반영점수를 분리해 기록한다.
- 리더보드 반영점수는 `원점수 × QUIZ_SCORE_MULTIPLIER`로 계산한다.
- `QUIZ_SCORE_MULTIPLIER` 초기값은 3이다.
- 참가자 리더보드 총점은 0보다 작아질 수 없다.
- 감점 후 총점은 `max(0, 현재 총점 + 요청된 감점)`으로 계산한다.
- 0점 아래의 감점 잔액을 숨은 빚으로 남기지 않으며 이후 획득점수에서 차감하지 않는다.
- 감점 이벤트에는 요청된 감점 사유와 실제 적용된 리더보드 증감값을 모두 감사 가능하게 기록한다.
- 모든 회차 및 역할별 점수 이벤트는 중복 생성되지 않아야 한다.

### 10.2 정산 우선순위

아래 네 상황은 상호 배타적으로 적용한다.

| 우선순위 | 상황 | 풀이자 원점수 | 풀이자 리더보드 | 기준 답안 작성자 리더보드 | 퀴즈 점수율 |
|---:|---|---:|---:|---:|---|
| 1 | 기준 답안 미입력 | 기본 3점 | +9 | 변동 없음 | 제외 |
| 2 | 기준 답안 입력, 풀이 답안 미제출 | 0점 | 0 | +3 | 0/5 포함 |
| 3 | 풀이 답안 제출, 평가 정상 완료 | 평가점수 1~5점 | 평가점수 × 3 | +3 | 평가점수/5 포함 |
| 4 | 풀이 답안 제출, 평가 미완료 | 자동 2점 | +6 | -6, 단 총점 최저 0 | 2/5 포함 |

### 10.3 기준 답안 미입력

- 기준 답안 입력기간 내에 기준 답안이 확정되지 않으면 풀이자에게 문제를 제공하지 않는다.
- 풀이자는 해당 풀이기간을 쉰다.
- 풀이기간 종료 시 풀이자에게 3점을 평가받은 것과 동일한 리더보드 점수 `3 × 배수`를 지급한다.
- 기준 답안 작성자에게 별도의 보상이나 감점을 주지 않는다.
- 이 기본점수는 퀴즈 점수율의 분자와 분모에 포함하지 않는다.

### 10.4 풀이 답안 미제출

- 기준 답안은 확정됐지만 풀이 답안이 제출되지 않으면 풀이자의 원점수는 0점이다.
- 풀이자에게 리더보드 점수를 지급하지 않는다.
- 기준 답안 작성자에게 1점을 평가받은 것과 동일한 보상 `1 × 배수`를 자동 지급한다.
- 평가자가 수행할 평가 작업은 생성하지 않는다.
- 해당 회차는 풀이자의 퀴즈 점수율에 `0/5`로 포함한다.

### 10.5 정상 평가

- 평가자가 1점부터 5점 중 하나를 확정하면 그 값이 풀이자의 원점수다.
- 풀이자에게 `평가점수 × 배수`를 지급한다.
- 평가를 완료한 참가자에게 `1 × 배수`를 평가 완료 보상으로 지급한다.
- 해당 회차는 풀이자의 퀴즈 점수율에 `평가점수/5`로 포함한다.

### 10.6 평가 미완료

- 풀이 답안이 제출됐지만 평가기간 내 평가가 확정되지 않으면 풀이자의 원점수를 2점으로 자동 확정한다.
- 풀이자에게 `2 × 배수`를 지급한다.
- 평가 미완료 참가자에게 `-2 × 배수` 감점을 요청한다.
- 감점 적용 후 총점이 음수가 되면 0점으로 제한한다.
- 평가 완료 보상은 함께 지급하지 않는다.
- 해당 회차는 풀이자의 퀴즈 점수율에 `2/5`로 포함한다.

## 11. 퀴즈 점수율

### 11.1 계산식

```text
퀴즈 점수율 =
  정산 대상 회차의 풀이 원점수 합계
  / (기준 답안이 정상 확정된 정산 대상 회차 수 × 5)
  × 100
```

### 11.2 포함 규칙

- 정상 평가점수 1~5점은 그대로 포함한다.
- 풀이 답안 미제출은 0점으로 포함한다.
- 평가 미완료 자동점수는 2점으로 포함한다.
- 기준 답안 미입력으로 받은 기본 3점은 제외한다.
- 평가자의 완료 보상과 미평가 감점은 제외한다.
- 리더보드 적용 배수는 제외한다.
- 취소된 회차와 질문 풀 소진으로 생성되지 않은 회차는 제외한다.

### 11.3 저장과 표시

- 회차별 정산 원점수와 최대점수 5를 보존한다.
- 백분율만 누적 저장하지 않고 원점수 합계와 최대점수 합계를 계산 가능하게 유지한다.
- 최대점수 합계가 0이면 `0%`가 아니라 `산출 불가` 또는 `-`로 표시한다.
- 화면 표시 시 소수점 첫째 자리까지 반올림한다.
- 진행 중에는 본인의 회차별 평가 결과만 확인할 수 있다.
- 팀 결과가 공개된 뒤 전체 최종 리더보드에 모든 참가자의 최종 퀴즈 점수율을 표시한다.
- 수동 결과 공개 팀은 `MANUAL_RELEASED`, 자동 결과 공개 팀은 `AUTO_RELEASED` 상태가 된 뒤에만 전체 점수율을 공개한다.

## 12. 알림

### 12.1 전송 채널

- 필수 알림은 인앱 알림으로 저장한다.
- 사용자가 푸시 알림을 허용한 기기에는 동일 이벤트의 웹 푸시도 전송한다.
- 푸시 권한이 없거나 등록 기기가 없어도 인앱 알림 생성은 성공해야 한다.
- 푸시 잠금화면 본문에는 질문, 기준 답안, 풀이 답안 원문을 넣지 않는다.
- 알림 CTA는 해당 팀의 관리자 설정 또는 참가자 `비밀 퀴즈` 메뉴로 이동한다.

### 12.2 필수 알림 이벤트

| 이벤트 | 수신자 | 시점 | 완료 조건 |
|---|---|---|---|
| 전원 Claim 완료 | 팀 관리자 | 최초 전원 Claim 완료 직후 | 관리자가 확인 또는 퀴즈 모드 활성화 |
| 새 회차 및 기준 답안 입력 | 모든 참가자 | 회차 입력기간 시작 | 본인의 기준 답안 확정 |
| 풀이기간 시작 | 유효한 문제가 있는 풀이자 | 풀이기간 시작 | 풀이기간 종료 |
| 평가 가능 | 제출된 풀이 답안이 있는 평가자 | 평가기간 시작 | 평가 확정 또는 자동 정산 |
| 종료 예정일 충돌 | 팀 관리자 | 충돌 회차 입력기간 시작 | 진행 또는 취소 결정 |
| 질문 풀 소진 | 팀 관리자 | 새 회차 생성 실패 시 | 관리자 확인 |
| 조건부 회차 취소 | 해당 팀 참가자 | 관리자 취소 또는 미응답 자동 취소 시 | 일반 읽음 처리 |

### 12.3 읽음과 할 일 상태 분리

- 알림 읽음 상태와 퀴즈 할 일 완료 상태를 분리한다.
- 사용자가 알림을 열거나 전체 알림을 읽음 처리해도 미완료 퀴즈 강조는 사라지지 않는다.
- 기준 답안 미확정 강조 여부는 현재 회차와 기준 답안 상태에서 계산한다.
- 기준 답안을 확정하면 관련 회차 시작 알림을 읽음 처리한다.
- 알림 레코드가 보존 정책에 따라 삭제돼도 진행 중 할 일 상태는 퀴즈 데이터에서 계산할 수 있어야 한다.

- 전역 Navbar 알림 버튼의 왼쪽 아래에 겹쳐 배치한다.
- 현재 기준 답안 입력기간이면서 사용자가 아직 기준 답안을 확정하지 않았을 때만 표시한다.
- 알림을 읽었는지와 관계없이 미완료 상태가 유지되는 동안 표시한다.
- 기준 답안 확정, 입력기간 만료, 회차 취소 또는 팀 종료 시 즉시 숨긴다.
- 풀이 또는 평가 미완료에는 이 강한 이미지 강조를 사용하지 않고 일반 알림만 사용한다.

### 13.3 확대·축소 펄스

- 에셋은 반복적인 확대·축소 펄스 애니메이션으로 강조한다.
- 깜빡임 애니메이션은 사용하지 않는다.
- 애니메이션은 부드러운 `ease-in-out` 형태로 계속 반복한다.
- 레이아웃 크기는 바꾸지 않고 CSS `transform: scale(...)`로만 확대·축소한다.
- `prefers-reduced-motion: reduce` 환경에서는 애니메이션을 중지하고 정적인 강조 이미지로 표시한다.

## 14. 익명성과 접근 통제

### 14.1 풀이자 신원 보호

- 팀 결과 공개 전 평가자는 자신을 챙기는 풀이자의 실명, 사용자 ID, Participant ID, 프로필 또는 식별 가능한 필드를 받을 수 없다.
- 평가 화면에는 `나를 챙기는 마니또의 답안`으로만 표시한다.
- 결과 공개 전 `나를 챙겨주는 마니또`의 `counterpart_name`은 반드시 `null`이어야 한다.
- 이 제한은 퀴즈 REST 응답, 이력 응답, 알림 데이터 및 WebSocket/실시간 이벤트에 동일하게 적용한다.

### 14.2 답안 공개 범위

- 풀이기간 동안 풀이자에게 기준 답안을 노출하지 않는다.
- 평가자는 평가가 가능해진 이후에만 자신에 관한 풀이 답안을 볼 수 있다.
- 풀이자는 평가 확정 또는 자동 정산 뒤에만 기준 답안과 평가점수를 볼 수 있다.
- 관리자는 참가자별 제출 여부와 진행 현황은 볼 수 있지만 질문별 기준 답안, 풀이 답안 원문 또는 평가 내용을 볼 수 없다.
- 관리자가 팀 참가자이기도 한 경우에는 자신의 참가자 역할로 허용되는 답안만 볼 수 있다.

### 14.3 서버 권한 검증

- 모든 조회와 변경 API는 요청 사용자가 해당 팀의 Claim된 Participant인지 검증한다.
- 관리자 설정과 종료 예정일 결정 API는 팀 owner인지 검증한다.
- 클라이언트가 보낸 Participant, 풀이자, 평가자 식별값을 신뢰하지 않고 서버 관계에서 계산한다.
- 마감과 상태 검증은 서버 시각을 기준으로 한다.

## 15. 시스템 기본 질문 시드

### 15.1 원천 파일

- 원천 파일은 프로젝트의 `tmp/quizes_raw.md`다.
- 파일은 UTF-8로 읽는다.
- 원천 파일에는 5개 분류와 1번부터 50번까지 총 50개 질문이 있다.
- 질문 내용의 적절성 검토, 표현 수정, 맞춤법 수정 또는 문체 변경은 이 기능 구현 범위에 포함하지 않는다.
- 구현자는 질문 본문을 임의로 검토하거나 고치지 않고 원문 그대로 파싱한다.

### 15.2 파싱 규칙

- `### `로 시작하는 줄을 분류 헤더로 인식한다.
- `숫자. 질문 본문` 형식의 줄을 질문으로 인식한다.
- 숫자 접두사는 원본 번호로 보존하고 질문 본문에는 포함하지 않는다.
- 질문 본문은 숫자 접두사와 그 뒤 한 칸을 제외하고 원문 그대로 보존한다.
- 각 질문에는 원본 번호에 대응하는 안정적인 ID를 부여한다.
  - 예: 1번은 `SYSTEM_001`, 50번은 `SYSTEM_050`
- 원본 순서와 분류 소속을 보존한다.
- 파싱 결과가 다음 조건을 충족하지 않으면 시드 생성을 실패시킨다.
  - 분류 5개
  - 질문 50개
  - 원본 번호 1부터 50까지 연속
  - 질문 ID와 원본 번호 중복 없음
  - UTF-8 대체문자 없음

### 15.3 추적 가능한 시드 데이터

- `tmp/`는 Git 추적 대상이 아니므로 런타임에서 원천 MD를 직접 읽지 않는다.
- 파싱 결과는 프로젝트가 Git으로 추적하는 UTF-8 시드 데이터로 옮긴다.
- 시드 데이터에는 최소한 다음 값을 포함한다.
  - 안정적인 질문 ID
  - 원본 번호
  - 분류
  - 질문 본문
  - 활성 상태
  - 표시 순서
- 시드 로딩은 질문 ID를 기준으로 멱등하게 동작해야 하며 반복 실행해도 중복 질문을 만들지 않는다.
- 배포 환경은 추적된 시드 데이터만 사용하고 `tmp/quizes_raw.md`의 존재에 의존하지 않는다.

## 16. 데이터 보존과 삭제

- 질문 배정 이력, 기준 답안, 풀이 임시 저장본, 제출 답안, 평가 및 정산 결과는 Team에 귀속한다.
- 팀 종료 후 결과 공개 기간에는 기존 접근 권한에 따라 최종 결과를 제공한다.
- 질문 원문 스냅샷, 기준 답안 및 풀이 답안 원문은 팀과 함께 종료 7일 후 영구 삭제한다.
- 회차별 원점수, 퀴즈 점수율 및 최종 리더보드도 별도의 장기 보존본을 만들지 않고 팀과 함께 삭제한다.
- 삭제 전까지 최종 퀴즈 점수율은 결과 공개된 전체 최종 리더보드에서 확인할 수 있다.
- 퀴즈 답안 원문을 로그, 푸시 payload 또는 분석 이벤트에 복사해 장기 보존하지 않는다.

## 17. 자동 처리와 일관성

- 회차 시작, 기간 전환, 자동 제출, 자동 정산 및 점수 반영의 기준은 서버다.
- 사용자가 해당 시각에 접속하지 않아도 상태와 정산 결과가 같아야 한다.
- 예약 작업이 늦게 실행되더라도 저장된 회차 마감 시각을 기준으로 결과를 계산한다.
- 동일 자동 작업이 재시도되거나 여러 서버 인스턴스에서 동시에 실행돼도 다음 결과가 중복되면 안 된다.
  - 회차 생성
  - 참가자별 질문 배정
  - 자동 제출
  - 기본점수 지급
  - 0점 정산
  - 자동 2점 정산
  - 평가 보상
  - 미평가 감점
  - 알림 생성
- 점수 이벤트와 Participant 리더보드 총점 변경은 하나의 트랜잭션으로 처리한다.
- 회차 상태 변경과 관련 알림/실시간 갱신은 데이터 커밋 이후에 발행한다.
- 자동 정산과 사용자의 마감 직전 요청이 경합하면 서버가 트랜잭션에서 확정한 요청 시각과 마감 시각으로 한 번만 결정한다.

## 18. 완료 기준

다음 조건을 모두 검증해야 기능이 완료된 것으로 본다.

### 18.1 설정과 일정

- 전원 Claim 전에는 퀴즈를 켤 수 없다.
- 최초 전원 Claim 완료 시 관리자 알림이 생성된다.
- 활성화 후 가장 먼저 도래하는 관리자 시간대의 기준 시간에 첫 회차가 시작된다.
- 입력일수와 풀이일수의 각 최소값 및 합계 최대값 검증이 동작한다.
- 기간 변경이 진행 중 회차를 바꾸지 않고 다음 회차부터 적용된다.
- 퀴즈 OFF 이후 새 회차는 생성되지 않지만 기존 회차는 정산된다.

### 18.2 질문과 답안

- 관리자 공통 질문은 전원에게 동일하게 한 번 적용된다.
- 공통 질문이 없으면 참가자별 시스템 기본 질문이 고정 배정된다.
- 동일 Participant에게 같은 질문이 재배정되지 않는다.
- 기준 답안은 확인 후 한 번만 확정되고 변경되지 않는다.
- 풀이 답안은 기간 중 수정 가능하며 마지막 저장본만 자동 제출된다.
- 평가점수는 한 번만 확정되고 변경되지 않는다.

### 18.3 예외와 점수

- 네 가지 점수 정산 상황이 우선순위표와 일치한다.
- 동일 회차를 여러 번 처리해도 점수가 중복되지 않는다.
- 감점으로 리더보드 총점이 0 미만이 되지 않는다.
- 0점 아래의 감점 빚이 남지 않는다.
- 기준 답안 미입력 기본점수가 퀴즈 점수율에서 제외된다.
- 조기 종료 시 완료된 정산만 유지되고 미정산 회차는 점수 없이 취소된다.

### 18.4 종료 예정일

- 풀이기간에 종료 예정일이 포함된 회차에서 관리자 결정 알림이 생성된다.
- 진행 승인 전에는 결정 대기 상태가 참가자에게 표시된다.
- 취소 또는 미응답 시 회차 점수가 발생하지 않고 퀴즈 모드가 꺼진다.
- 진행 승인 후에는 정상 풀이기간으로 전환된다.

### 18.5 알림과 강조

- 기준 답안 입력, 풀이 시작, 평가 시작 알림이 올바른 수신자에게 생성된다.
- 전체 읽음 처리 후에도 미확정 기준 답안 강조가 유지된다.
- 기준 답안 확정 즉시 강조가 사라진다.
- 변환된 WebP가 50KB 미만이다.
- Navbar 알림 버튼 왼쪽 아래에서 확대·축소 펄스가 동작한다.
- 모션 감소 환경에서는 정적인 에셋으로 표시된다.

### 18.6 익명성과 결과

- 결과 공개 전 나를 챙기는 마니또의 `counterpart_name`이 모든 관련 응답에서 `null`이다.
- 평가자는 풀이자의 실명이나 식별자를 알 수 없다.
- 풀이기간에는 풀이자에게 기준 답안이 노출되지 않는다.
- 관리자는 답안 원문을 볼 수 없다.
- 결과 공개 후 전체 최종 리더보드에 참가자별 퀴즈 점수율이 표시된다.
- 종료 7일 후 팀 삭제와 함께 퀴즈 원문 및 결과 데이터가 삭제된다.

### 18.7 질문 시드

- `tmp/quizes_raw.md`를 UTF-8로 파싱한다.
- 질문 본문을 수정하지 않는다.
- 해당 md파일에 존재하는 질문 세트를 시드 데이터로 생성한다.
- 질문 ID가 `SYSTEM_001`부터 `SYSTEM_XXX`까지 안정적으로 대응한다.
- 시드 로딩을 반복해도 중복 데이터가 생성되지 않는다.
- 배포 런타임이 `tmp/quizes_raw.md`에 의존하지 않는다.
- `tmp/quizes_raw.md`에 들어갈 내용은 아직 확정이 아니므로 질문 수/형식 변화 등에 따른 유동적인 파싱 전략을 구상한다.
